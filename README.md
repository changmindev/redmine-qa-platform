# Redmine QA 플랫폼

**이슈 트래커에서 릴리스 판단까지, QA 사이클을 자동화하는 개인 사이드 프로젝트입니다.**

QA 업무를 하며 반복되던 수작업 — 이슈를 하나씩 열어 테스트케이스를 손으로 쓰고,
결과를 엑셀에 옮기고, 실패 건을 다시 이슈로 타이핑하고, "지금 출시해도 되나?"를
감으로 판단하는 과정 — 을 직접 자동화해보고 싶어서 만들었습니다.

Claude 를 단순 텍스트 생성기가 아니라 **"이 결과를 사람 검수 없이 믿어도 되는가"를
스스로 판단하는 파이프라인**으로 설계한 것이 이 프로젝트의 핵심입니다. 자세한 이유는
[DECISIONS.md](DECISIONS.md)에 있습니다.

```
                  ┌──────────────────────────────────────────┐
   ┌──────────┐   │            Flask 백엔드                   │   ┌──────────┐
   │ Redmine  │──▶│  수집 → 분석 → 생성 → 저장 → 판정         │◀──│  Claude  │
   │ (이슈)    │◀──│                                          │   │ SDK/CLI  │
   └──────────┘   └───────────────┬──────────────────────────┘   └──────────┘
     결함 등록                     │
                    ┌─────────────┴─────────────┐
                    ▼                           ▼
          📊 이슈 현황 리포트            🧪 테스트케이스 생성기
          · 릴리스 준비도 신호등          · 이슈 / 기획서로 케이스 생성
          · 담당자 워크로드·병목          · P/F 기록 · 결함 등록
          · 요구사항 추적 매트릭스        · 변경 이력 비교
```

> 포트폴리오 공개용 저장소입니다. 실제 운영 데이터·접속 정보·API 키는 포함돼 있지
> 않으며, 설정은 모두 `.env.example` 의 예시 값으로 대체돼 있습니다.

---

## 핵심 기능

**📊 이슈 현황 리포트** — 목표 버전을 고르면 "출시해도 되나?"에 점수가 아니라
막힌 이유(미해결 Blocker, 미실행 P0 케이스 등)로 답하는 릴리스 준비도 신호등,
우선순위 가중 워크로드·병목 진단, 재오픈율·처리시간 추이를 보여줍니다.

**🧪 테스트케이스 생성기** — Redmine 이슈(본문·코멘트·첨부) 또는 기획서
(PDF/워드/이미지/Figma)를 넣으면 우선순위·기능분류·절차·기대결과가 채워진
표로 생성합니다. 결과를 바로 기록해 실패 건은 버튼 한 번으로 결함 등록까지 됩니다.

**📋 요구사항 추적 매트릭스(RTM)** — 이슈 → 테스트케이스 → 실행결과 → 결함을
한 표로 묶어 "이 기능 테스트했어?"에 근거를 제시합니다.

## AI를 이렇게 썼습니다

단순히 프롬프트 하나로 텍스트를 뽑아내는 방식이 아니라, **결과의 신뢰도까지
시스템이 판단하게** 설계했습니다.

- **근거(evidence) 기반 신뢰도 판정** — 생성된 케이스마다 그 근거가 된 원문을
  한 문장 인용하게 하고, 근거가 없으면 빈 문자열로 남기도록 프롬프트에 못박았습니다.
  근거가 없는 케이스는 자동으로 "검수 필요"로 분리되어, **이 세트를 사람 확인
  없이 그대로 실행해도 되는지를 시스템이 판단**합니다.
- **프롬프트를 양식/공통 기준/프로젝트 지침 3단으로 분리** — 출력 형식과 QA
  설계 기법(동등분할·경계값·상태전이 등)은 고정하고, 프로젝트별 규칙만 뒤에
  덧붙는 구조로 짜서 프로젝트가 바뀌어도 산출물 품질이 흔들리지 않게 했습니다.
- **생성 목적(purpose)에 따라 다른 신뢰 수준** — "전체 검증"은 근거 없는 케이스도
  포함해 빠짐없이 덮고, "핵심 흐름"은 판정이 확실한 것만 남겨 무검수 자동 실행을
  전제로 합니다. 비율은 지시하지 않고 결과로만 남게 해 모델이 숫자 맞추기로
  빈 케이스를 채우는 걸 막았습니다.
- **구조화 출력 + 이중 백엔드** — 종량제 API 키가 있으면 JSON Schema 로 출력
  형식을 강제해 파싱 실패를 사실상 없앴고, 없으면 로컬 `claude` CLI(구독 인증)로
  자유 텍스트를 받아 직접 파싱·검증합니다. 비용과 가용성을 사용자가 고르게 했습니다.
- **멀티모달 입력** — 기획서가 PDF/워드/이미지/Figma 어떤 형태로 오든 텍스트로
  통일해 같은 생성 파이프라인을 태웁니다. 이미지는 Claude 비전으로 화면을 읽어
  "무엇을 검증할 수 있는 글"로 바꾼 뒤 사람이 확인하고 생성으로 넘깁니다.

## 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 백엔드 | Python 3.10+, Flask 3 (애플리케이션 팩토리 + Blueprint) |
| AI | Anthropic Claude — SDK(구조화 출력) / CLI(구독 인증) 이중 백엔드, Vision |
| 외부 연동 | Redmine REST API (재시도·페이지네이션), Figma API |
| 산출물 | openpyxl(xlsx, 조건부 서식), pdfkit(PDF, 선택) |
| 프론트 | 프레임워크 없는 순수 HTML/CSS/JS, 디자인 토큰 기반 스타일시트 |
| 품질 | pytest 172케이스(외부 호출 전부 mock), ruff, DOM 계약 검사기 |

## 빠른 시작

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # REDMINE_URL / REDMINE_API_KEY / REDMINE_PROJECT_ID 입력
python app.py
```

Claude 인증은 둘 중 하나면 됩니다 — 로컬에 `claude` CLI 를 설치·로그인해두거나
(`.env` 의 `ANTHROPIC_API_KEY` 를 비워둠), `console.anthropic.com` 에서 발급한
API 키를 `.env` 에 넣습니다.

| 주소 | 화면 |
|---|---|
| `http://localhost:5000` | 이슈 현황 리포트 |
| `http://localhost:5000/testcases` | 테스트케이스 생성기 |
| `http://localhost:5000/healthz` | 설정 점검 |

Windows 는 `start.bat`, macOS/Linux 는 `sh start.sh` 로 가상환경 생성부터
`.env` 편집까지 한 번에 안내받을 수 있습니다. 전체 설정 항목은
[`.env.example`](.env.example) 참고.

## 프로젝트 구조

```
redmine_report/
├── api/          # HTTP 계층 — 검증하고 services/ 를 호출할 뿐
├── services/     # 도메인 계층 — Flask 를 모른다 (단위 테스트 용이)
│   ├── redmine.py     # REST 클라이언트 (재시도·페이지네이션)
│   ├── ai.py           # 프롬프트 조립 · Claude 호출 · JSON 파싱
│   ├── quality.py      # 릴리스 준비도 · 추적 매트릭스
│   ├── analyzer.py      # 이슈 → 통계 · 워크로드
│   ├── extract.py       # PDF/워드/이미지/Figma → 텍스트
│   └── storage.py       # 세트/지침/리비전 저장 (원자적 쓰기)
├── static/, templates/  # 디자인 시스템 + 화면
tools/check_dom_contract.py   # 템플릿 무결성 검사 (id·CSS·JS 문법)
tests/                         # pytest 172케이스
```

## 설계 하이라이트

전체 판단 근거는 [DECISIONS.md](DECISIONS.md)에 정리했습니다. 그중 몇 가지:

- **통과율의 분모에서 미시행을 뺐다** — `Pass ÷ (Pass+Fail)`. 미시행을 분모에
  넣으면 테스트를 안 할수록 통과율이 떨어져 진행률과 뒤섞인다.
- **출시 판정에 점수를 매기지 않았다** — "82점"은 액션을 알려주지 않는다.
  막힌 이유("미실행 P0 3건")를 그대로 나열해 PM 이 바로 판단하게 했다.
- **워크로드를 건수가 아니라 우선순위 가중치로 셌다** — 긴급 2건과 낮음
  5건은 부하가 다르다.
- **서버가 임의 주소를 대신 요청하지 않는다** — URL 을 읽어오는 기능을 Figma 만
  화이트리스트로 허용해 내부망 자원을 긁어오는 SSRF 통로를 막았다.
- **엑셀/CSV 출력에서 수식 주입(Formula Injection)을 막았다** — 이슈 제목이
  `=`, `+` 로 시작하면 openpyxl 이 그 셀을 자동으로 "수식"으로 저장해, 파일을
  여는 사람 PC 에서 그대로 실행된다. 값을 텍스트로 강제하고 회귀 테스트로 고정했다.
- **CLI 호출은 셸을 거치지 않는다** — `subprocess.run` 에 인자 리스트로 넘겨
  명령 주입 경로를 원천 차단했다.
- **세트 ID 를 정규식으로 검증한다** — API 경로가 곧 파일 경로가 되므로
  `../` 경로 조작을 막는다.

## 알려진 한계

로그인이 없어 모든 사용자가 같은 Redmine API 키를 씁니다. 로컬에서 소수
사용자가 쓰는 것을 전제로 한 설계이며 (`HOST` 기본값이 `127.0.0.1`인 이유),
여러 명이 같은 회차를 동시에 편집하면 마지막 저장이 이전 내용을 덮어씁니다.

## 보안 · 데이터 취급

- `.env` 는 `.gitignore` 에 포함되어 커밋되지 않습니다.
- `data/`, `reports/` 는 실제 이슈 내용을 담으므로 외부 공유 시 제외해야 합니다.
- 이 저장소에는 실제 운영 데이터·접속 정보·API 키가 포함돼 있지 않습니다.
