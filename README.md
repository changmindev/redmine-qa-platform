# Redmine QA 플랫폼

**이슈 트래커에서 릴리스 판단까지, QA 사이클의 반복 작업을 줄이는 개인 사이드 프로젝트입니다.**

QA 업무에서 반복되던 일이 출발점입니다. 이슈를 하나씩 열어 테스트케이스를 손으로 쓰고,
결과를 엑셀에 옮기고, 실패 건을 다시 이슈로 타이핑하고, "지금 출시해도 되나?"를
감으로 판단하던 과정을 직접 자동화해 보려고 만들었습니다.

핵심은 Claude 를 글 생성기로만 쓰지 않은 점입니다. 생성된 케이스마다 원문 근거를 붙이게 해서
**"이 결과를 사람 검수 없이 믿어도 되는가"를 파이프라인이 판단**합니다.
왜 그렇게 설계했는지는 [DECISIONS.md](DECISIONS.md)에 있습니다.

```
                  ┌──────────────────────────────────────────┐
   ┌──────────┐   │            Flask 백엔드                   │   ┌──────────┐
   │ Redmine  │──▶│  수집 → 분석 → 생성 → 저장 → 판정         │◀──│  Claude  │
   │ (이슈)    │◀──│                                          │   │ SDK/CLI  │
   └──────────┘   └──────┬───────────────┬──────────────┬────┘   └──────────┘
   결함 등록(2단계)        │               │              │◀── JUnit XML
                         ▼               ▼              ▼     (Playwright·pytest·WDIO)
             이슈 현황 리포트    테스트케이스 생성기     자동화 결과
             · 릴리스 준비도     · 이슈/기획서로 생성    · 지난 실행 대비 비교
             · 워크로드·병목     · P/F 기록·결함 등록    · 불안정 TC 모음
             · 추적 매트릭스     · 변경 이력 비교
```

> 포트폴리오 공개용 저장소입니다. 실제 운영 데이터·접속 정보·API 키는 포함돼 있지
> 않으며, 설정은 모두 `.env.example` 의 예시 값으로 대체돼 있습니다.

## 핵심 기능

**이슈 현황 리포트** — 목표 버전을 고르면 "출시해도 되나?"에 점수 대신
막힌 이유(미해결 Blocker, 미실행 P0 케이스 등)로 답하는 릴리스 준비도 신호등을 보여 줍니다.
우선순위 가중 워크로드·병목, 재오픈율·처리시간 추이도 함께 봅니다.

**테스트케이스 생성기** — Redmine 이슈(본문·코멘트·첨부)나 기획서
(PDF/워드/이미지/Figma)를 넣으면 우선순위·기능분류·절차·기대결과가 채워진 표가 나옵니다.
결과를 바로 기록할 수 있고, 실패 건은 **미리보기에서 사람이 확인한 뒤에만** 결함으로
등록됩니다. 확인 토큰 없는 등록은 서버가 거절하므로 스크립트·AI 도구도 같은 2단계를 거칩니다.

**자동화 결과** — Playwright·pytest·WebdriverIO 가 내보내는 JUnit XML 을 올리면
지난 실행과 비교해 **새 실패 / 계속 실패 / 고쳐짐 / 사라진 TC** 로 나눠 보여 줍니다.
통과와 실패가 자꾸 뒤바뀌는 **불안정 TC** 는 따로 모읍니다. CI 에서 올릴 때는
`curl -F suite=이름 -F file=@results.xml http://<주소>/api/auto/runs` 한 줄이면 됩니다.
이 저장소 자체의 CI(`.github/workflows/ci.yml`)는 pytest·ruff·DOM 계약 검사만 돌립니다 — 이 서버를
올려 두고 결과를 받는 배포 환경이 아니라서, 자기 자신에게 이 API 를 호출하지는 않습니다.

**요구사항 추적 매트릭스(RTM)** — 이슈 → 테스트케이스 → 실행결과 → 결함을
한 표로 묶어 "이 기능 테스트했어?"에 근거로 답합니다.

## AI를 이렇게 썼습니다

프롬프트 문구만으로 맡기지 않고, 코드에서 정해 둔 규칙들입니다.

- **근거(evidence) 기반 신뢰도 판정** — 케이스마다 근거가 된 원문을 한 문장
  인용하게 하고, 근거가 없으면 빈 문자열로 남기라고 프롬프트에 정해 두었습니다.
  근거가 빈 케이스는 "검수 필요"로 자동 분리되므로, **이 세트를 사람 확인 없이
  실행해도 되는지**가 결과에 바로 드러납니다.
- **고정 영역과 프로젝트 지침을 분리** — 출력 양식과 공통 기준(동등분할·경계값·
  상태전이 등 설계 기법, 우선순위 정의)은 코드에 고정하고, 프로젝트별 규칙만 화면에서
  덧붙입니다. 프로젝트가 바뀌어도 산출물 품질의 바닥이 흔들리지 않게 하려는 구조입니다.
- **생성 목적(purpose)에 따라 다른 신뢰 수준** — "전체 검증"은 근거 없는 케이스도
  포함해 빠짐없이 덮고, "핵심 흐름"은 판정이 확실한 것만 남겨 무검수 자동 실행을
  전제로 합니다. 비율은 지시하지 않고 결과로만 남게 해 모델이 숫자 맞추기로
  빈 케이스를 채우는 걸 막았습니다.
- **구조화 출력 + 이중 백엔드** — 종량제 API 키가 있으면 JSON Schema 로 출력
  형식을 강제해 파싱 실패를 거의 없앴고, 없으면 로컬 `claude` CLI(구독 인증)로
  자유 텍스트를 받아 직접 파싱·검증합니다. 비용과 가용성을 사용자가 고르게 했습니다.
- **멀티모달 입력** — 기획서가 PDF/워드/이미지/Figma 어떤 형태로 오든 텍스트로
  통일해 같은 생성 파이프라인을 태웁니다. 이미지는 Claude 비전으로 화면을 읽어
  "무엇을 검증할 수 있는 글"로 바꾼 뒤 사람이 확인하고 생성으로 넘깁니다.
  이미지 분석은 API 키(SDK) 경로에서만 되고, Figma 는 `FIGMA_TOKEN` 이 필요합니다.

## 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 백엔드 | Python 3.10+, Flask 3 (애플리케이션 팩토리 + Blueprint) |
| AI | Anthropic Claude — SDK(구조화 출력) / CLI(구독 인증) 이중 백엔드, Vision |
| 외부 연동 | Redmine REST API (재시도·페이지네이션), Figma API |
| 입력 처리 | pypdf(PDF), 표준 라이브러리 zip/XML(워드, JUnit XML) |
| 산출물 | openpyxl(xlsx, 조건부 서식), pdfkit(PDF, 선택) |
| 프론트 | 프레임워크 없는 순수 HTML/CSS/JS, 디자인 토큰 기반 스타일시트, Chart.js(CDN) |
| 품질 | pytest 197케이스(외부 호출 전부 mock), ruff, DOM 계약 검사기 |

## 빠른 시작

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # REDMINE_URL / REDMINE_API_KEY / REDMINE_PROJECT_ID 입력
python app.py
```

Claude 인증은 둘 중 하나면 됩니다 — 로컬에 `claude` CLI 를 설치·로그인해두거나
(`.env` 의 `ANTHROPIC_API_KEY` 를 비워둠), `console.anthropic.com` 에서 발급한
API 키를 `.env` 에 넣습니다.

| 주소 | 화면 |
|---|---|
| `http://localhost:5000` | 이슈 현황 리포트 |
| `http://localhost:5000/testcases` | 테스트케이스 생성기 |
| `http://localhost:5000/automation` | 자동화 결과 (지난 실행 대비 · 불안정 TC) |
| `http://localhost:5000/healthz` | 설정 점검 |

Windows 는 `start.bat`, macOS/Linux 는 `sh start.sh` 로 가상환경 생성부터
`.env` 편집까지 한 번에 안내받을 수 있습니다. 전체 설정 항목은
[`.env.example`](.env.example) 참고.

```
│   ├── analyzer.py      # 이슈 → 통계 · 워크로드
│   ├── extract.py       # PDF/워드/이미지/Figma → 텍스트
│   ├── automation.py    # JUnit XML 수집 · 지난 실행 대비 비교 · 불안정 TC
│   ├── tcdiff.py        # 테스트케이스 변경 이력 비교
│   ├── excel.py         # xlsx 내보내기 (수식 주입 방어)
│   └── storage.py       # 세트/지침/리비전 저장 (원자적 쓰기)
├── static/, templates/  # 디자인 시스템 + 화면
tools/check_dom_contract.py   # 템플릿 무결성 검사 (id·CSS·JS 문법)
tests/                         # pytest 197케이스
```

## 설계 하이라이트

전체 판단 근거는 [DECISIONS.md](DECISIONS.md)에 정리했습니다. 그중 몇 가지:

- **통과율의 분모에서 미시행을 뺐다** — `Pass ÷ (Pass+Fail)`. 미시행을 분모에
  넣으면 테스트를 안 할수록 통과율이 떨어져 진행률과 뒤섞인다.
- **출시 판정에 점수를 매기지 않았다** — "82점"은 액션을 알려주지 않는다.
  막힌 이유("미실행 P0 3건")를 그대로 나열해 PM 이 바로 판단하게 했다.
- **워크로드를 건수가 아니라 우선순위 가중치로 셌다** — 긴급 2건과 낮음
  5건은 부하가 다르다.
- **서버가 임의 주소를 대신 요청하지 않는다** — URL 을 읽어오는 기능을 Figma 만
  화이트리스트로 허용해 내부망 자원을 긁어오는 SSRF 통로를 막았다.
- **엑셀/CSV 출력에서 수식 주입(Formula Injection)을 막았다** — 이슈 제목이
  `=`, `+` 로 시작하면 openpyxl 이 그 셀을 자동으로 "수식"으로 저장해, 파일을
  여는 사람 PC 에서 그대로 실행된다. 값을 텍스트로 강제하고 회귀 테스트로 고정했다.
- **CLI 호출은 셸을 거치지 않는다** — `subprocess.run` 에 인자 리스트로 넘겨
  명령 주입 경로를 원천 차단했다.
- **세트 ID 를 정규식으로 검증한다** — API 경로가 곧 파일 경로가 되므로
  `../` 경로 조작을 막는다.

## 알려진 한계

로그인이 없어 모든 사용자가 같은 Redmine API 키를 씁니다. 로컬에서 소수
사용자가 쓰는 것을 전제로 한 설계이며 (`HOST` 기본값이 `127.0.0.1`인 이유),
여러 명이 같은 회차를 동시에 편집하면 마지막 저장이 이전 내용을 덮어씁니다.

## 보안 · 데이터 취급

- `.env` 는 `.gitignore` 에 포함되어 커밋되지 않습니다.
- 모든 응답에 `X-Content-Type-Options: nosniff` · `X-Frame-Options: DENY` 를 붙이고, 요청 본문 크기에 상한을 둡니다.
- PDF 리포트는 wkhtmltopdf 의 스크립트 실행·로컬 파일 접근을 끈 채로 만듭니다(pdfkit 1.0.0 에 고친 버전이 없는 CVE-2025-26240 대응).
- `data/`, `reports/` 는 실제 이슈 내용을 담으므로 외부 공유 시 제외해야 합니다.
- 이 저장소에는 실제 운영 데이터·접속 정보·API 키가 포함돼 있지 않습니다.
